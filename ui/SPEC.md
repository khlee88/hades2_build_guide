# 모바일 UI 명세 (3-A, 페이블)

> 구현: `app/index.html` **단일 파일** (데이터·엔진 인라인, 외부 라이브러리 없음, 바닐라 JS). Artifact로 배포 → 폰 브라우저에서 열고 홈 화면에 추가.
> 정본: 엔진 계약은 `engine/DESIGN.md §10`, 용어는 `data/SCHEMA.md` 대조표. 이 문서는 화면·조작·저장만 다룬다.

## 0. 사용 상황이 모든 결정을 정한다

- **게임은 PC 화면, 폰은 왼손/오른손 한 손.** 게임 선택지가 뜬 채로 폰을 보며 **3초 안에** "이거"를 얻어야 한다.
- 따라서: 타이핑 없음(검색은 보조), 탭 3번 이내로 추천 도달, 결과는 **1·2·3위가 위에서 아래로 크게**, 이유는 한 줄, 경고는 빨갛게.
- 주 조작은 **화면 하단 1/3(엄지 영역)**. 상단은 정보 표시만.
- 어두운 방에서 본다 → **다크 고정 테마**, 대비 높게. 라이트 모드 없음(색은 전부 명시적으로 칠한다).
- 게임 중 폰이 잠들었다 깨도 **그 화면 그대로** 있어야 한다 → 모든 상태 변경 즉시 저장.

## 1. 화면 목록과 흐름

```
[런 시작] ──시작──▶ [홈] ◀──결정──┐
                     │             │
        ┌────────────┼──────────┬──┴──────────┐
        ▼            ▼          ▼             ▼
    [신 선택]    [은혜 선택]  [망치 선택]   [관리]
        │ 문 결정      │ 추천→결정    │ 추천→결정    (체력·지역·기념품·비술·보유 편집·되돌리기·새 런)
        └──────────▶ 은혜 선택(그 신으로 필터)
```

- 앱 실행 시: 저장된 런이 있으면 **홈**(상단에 "이어하기 중 · 3지역" 표시), 없으면 **런 시작**.
- 홈 이외 화면은 전부 **모달 시트**(아래에서 올라옴). 닫으면 홈. 브라우저 뒤로가기 = 시트 닫기(`history.pushState`).

## 3. 화면별 명세

### 3-1. 런 시작
목적: 무기·양상 고르고, 시작 전 추천(아르카나·기념품·비술·열린 방향) 보고 시작.

1. **무기 4개 큰 카드**(2×2): 한글명 + 별칭(데스쿠라 등). 은백색 해골·검은빛 외투는 "준비 중" 회색.
2. 무기 탭 → **양상 4개** 가로 칩 (숨겨진 양상은 회색 + 🔒, 탭하면 "해금 후 사용"). 기본 멜리노에 양상 선택됨.
3. 아래로 `recommendRunStart` 결과:
   - **아르카나** 카드: 이해도 상한 스텝퍼(기본 10, 저장됨) → 카드 목록(이름·이해도·효과 1줄). `free_cards`는 접힌 섹션 "각성 조건 충족 시 무료" 로 분리.
   - **기념품** 3개(보유한 것만 — 보유 목록은 관리 화면에서 체크, 미설정이면 전부 표시).
   - **비술** 2개.
   - **열린 방향** 카드 N개: 이름·★난이도·핵심 칸·1순위 은혜·대표 융합·핵심 망치. 상단 문구 "첫 신이 뜨기 전엔 방향을 고정하지 않아요".
4. 하단 고정 **[이 무기로 시작]** 56px. 탭 → 새 state 생성(기존 런 있으면 확인 대화상자) → 홈.

### 3-2. 홈 (런 진행 중)
목적: 지금 빌드 상태를 한눈에, 다음 행동 버튼 4개.

**상단 — 지금 빌드 카드** (`directionScores` + state)
- 1행: 무기·양상 · `N지역` · 체력 상태 아이콘(●●○ 3단) — 각각 탭하면 관리 화면 해당 항목으로
- 2행: **메인 방향 이름** + 가중치 바(0~100%), 옆에 작게 보험 방향 이름
- 3행: **5칸 칩** — 채워진 칸은 신 색 배경 + 은혜 한글명(짧게), 빈 칸은 점선 테두리 "빈 칸". 메인 방향의 핵심 칸은 금색 점 표시
- 4행(접힘 기본): "다음에 원하는 것" `next_wants` 3개, 목표 융합 진행도 `n/m` 바 2~3개
- 우측 상단: **되돌리기** (↶, 마지막 선택 취소, 히스토리 10개)

**하단 고정 — 행동 버튼 2×2** (각 72px)
```
[ 신 선택 ]   [ 은혜 선택 ]
[ 망치 선택 ]  [ 관리 ]
```
- "은혜 선택"이 가장 자주 눌리므로 **오른쪽 위**(오른손 엄지 기본 위치). 왼손잡이 옵션 = 좌우 반전 토글(관리 화면).
- 방향 고정 중이면 카드에 🔒 표시.

### 3-3. 신 선택 (문 앞)
목적: 방 보상 문에 뜬 신 2~3명을 고르면 어느 문으로 갈지 답.

1. **신 그리드**: 핵심 9 + 헤르메스·아르테미스·셀레네·카오스 = 13개 원형 버튼(56px), 신 색 테두리, 한글명 아래 작게. 이미 은혜 받은 신은 ✓ 표시.
2. 2개 이상 선택되면 즉시 아래에 **추천 카드**(`recommendGods`): 1위 크게, 이유, 배지("새 신" 등). 재탭으로 해제.
3. 카드 탭 = **"이 문으로"** → `state.pending_god` 저장 → **은혜 선택 시트가 그 신으로 필터된 채 자동으로 열림**. (신을 실제로 만난 뒤 은혜를 고를 때까지 `gods_seen`은 건드리지 않는다 — `applyChoice(boon)`이 갱신)
4. 하단: [닫기].

### 3-4. 은혜 선택 — 가장 중요한 화면
목적: 게임에 뜬 은혜 3개를 찍고 1·2·3위를 본다. **탭 3~4번, 5초.**

레이아웃(위→아래):
1. **신 탭 바**(가로 스크롤, 56px): `pending_god`이 있으면 그 신이 선택된 채 열림. 그 외엔 마지막 선택 신. 탭마다 신 색.
2. **은혜 격자**: 선택된 신의 은혜를 **칸 순서(공·기·마·질·력) → 패시브 → 정기 → 전설 → 융합** 순으로. 각 항목 = 칩(칸 글자) + 한글명 + 효과 1줄(회색 14px). 한 신이 14개 + 융합 8개 ≈ 22개, 한 화면에 들어오게 행 높이 48px.
   - 융합은 "융합 (제우스·헤스티아)" 처럼 상대 신 표기. 전설은 금색 테두리.
   - 이미 보유한 은혜는 회색 + "보유". `prereq` 미충족(엔진 `blockReason`)은 회색 + "조건 미충족" — 탭은 되지만 추천에 불가로 뜸.
   - **검색**: 상단 🔍 아이콘 탭 시에만 입력창 등장(기본 숨김). 이름 부분 일치, 전 신 대상.
3. **선택 트레이**(하단 고정, 시트 안): 선택한 은혜 최대 3개를 칩으로. 각 칩 옆 작은 **희귀도 토글**(일반→희귀→특별→영웅 순환, 기본 일반, 융합/전설은 자동). 4번째 선택하면 가장 오래된 것 교체.
4. **2개 이상 선택되면 트레이 위에 추천 결과가 즉시 펼쳐짐**(`recommendBoons`). 버튼 안 눌러도 됨.

**추천 카드**(순위별 1장, 1위는 배경 강조):
```
┌ 1위 ───────────────────────── 12.4 ┐
│ [공] 대전된 마력                    │  ← 22px
│ Ω 빌드인데 마력 칸이 비었음          │  ← 이유 1줄
│ ⚑ 마력                             │  ← 배지 칩
│ ⚠ 천상 일격을 버리게 됨             │  ← 경고 빨강, 있을 때만
└─────────────────────── [이걸로 결정] ┘
```
- 점수는 오른쪽 위 작게 회색(디버그 성격). `breakdown`은 카드 길게 누르면(500ms) 토스트로.
- **선택 불가**(−∞)는 카드 회색 + 이유("상충: 고속 강타과 동시 불가"), 결정 버튼 없음.
- **[이걸로 결정]** → `applyChoice({kind:'boon', id, rarity})` → 히스토리 push → 저장 → 시트 닫힘 → 홈 카드 갱신 애니메이션 없이 즉시.
- 결정 버튼은 카드 **오른쪽 하단**(엄지). 1위 카드에만 크게, 2·3위는 작게.
- "게임에 뜬 게 목록에 없어요" 링크 → 검색 열림.

### 3-5. 망치 선택
은혜 선택과 동일 구조, 데이터만 `hammers`(현재 무기 것만, `aspect_only/excluded`는 엔진이 회색 처리). 신 탭 바 없음. 3개 선택 → `recommendHammers` → 결정 → `applyChoice({kind:'hammer'})`. 배지 "방향 전환: …"은 보라색으로 눈에 띄게.

### 3-6. 관리
세로 목록, 각 항목 56px:
1. **체력** ●●● / ●●○ / ●○○ 세그먼트 (high/mid/low) → 즉시 저장. 홈 카드에도 반영.
2. **지역** 1 2 3 4 세그먼트. 바꾸면 아래에 **기념품 추천**(`recommendKeepsake`) 카드가 뜨고 [이 기념품으로] 버튼 → `applyChoice({kind:'keepsake'})`.
3. **현재 기념품** 선택(보유 기념품 목록에서), **보유 기념품 편집**(33개 체크리스트 — prefs에 저장, 런과 무관).
4. **비술** 선택(9개, 현재 비술 표시).
5. **방향 고정**: 활성 방향 라디오 + "고정 해제". `state.direction_lock`.
6. **보유 은혜·망치 편집**: 리스트, 스와이프 없이 각 행 [×]로 제거(실수 수정용). 추가는 은혜 선택 시트를 "추천 없이 바로 추가" 모드로 열기.
7. **선택 기록**: 최근 10개 (시간·종류·이름), 되돌리기와 동일 스택.
8. **설정**: 왼손 모드, 이해도 상한, 점수 표시 on/off.
9. **새 런 시작**(빨간 테두리, 확인 대화상자) · **런 내보내기/불러오기**(state JSON을 텍스트 영역에 표시/붙여넣기 — 폰↔PC 이동용. 파일 다운로드는 Artifact에서 막히므로 텍스트로).

## 4. 상태·저장

### 4-1. 저장 키 (localStorage, 전부 try/catch)
| 키 | 내용 | 갱신 시점 |
|---|---|---|
| `h2.run.v1` | 엔진 state + UI 필드 `{pending_god, history:[{ts,kind,id,rarity,prev_state_diff}]}` | **모든 변경 즉시** (결정·체력·지역·기념품·비술·고정·편집·되돌리기) |
| `h2.prefs.v1` | `{owned_keepsakes:[], grasp_cap:10, left_hand:false, show_score:true, last_weapon, last_aspect}` | 해당 설정 변경 시 |
| `h2.ui.v1` | `{screen, god_tab, sheet_scroll}` — 재진입 시 같은 화면 복원 | 화면 전환 시 |

- 저장 실패(사파리 프라이빗 등) 시 상단에 얇은 노란 띠 "저장 안 됨 — 이 탭을 닫으면 사라져요". 기능은 계속 동작.
- 스키마 버전 `v1`. 나중에 필드가 바뀌면 키를 올리고 구버전은 읽어서 변환 시도, 실패 시 무시.

### 4-2. 되돌리기
- `history` 스택에 결정 직전 state 스냅샷(JSON 문자열) 최대 10개. 되돌리기 = pop 후 복원. 관리 화면 기록 목록과 같은 데이터.

### 4-3. 엔진 호출 지점
| 화면 | 호출 |
|---|---|
| 런 시작 | `recommendRunStart(weapon, aspect, {graspCap, ownedKeepsakes})` |
| 홈 카드 | `directionScores(state)`, `validateState(state)`(경고 있으면 카드 상단 노란 줄) |
| 신 선택 | `recommendGods(state, selected)` |
| 은혜 선택 | `recommendBoons(state, selected.map(({id,rarity})))` |
| 망치 선택 | `recommendHammers(state, selected)` |
| 관리>지역 변경 | `recommendKeepsake(state)` |
| 결정 | `applyChoice(state, choice)` → 저장 |

전부 동기 호출, 100ms 이내여야 한다(데이터 345항목, 문제 없음). 결과가 비면 "추천할 게 없어요 — 선택지를 2개 이상 찍어 주세요".

## 5. 빌드 (3-B가 만들 것)

- `app/build.js`: `data/*.json` + `engine/weights.js` + `engine/recommend.js` + `app/src/*.{html,css,js}` → **`app/index.html` 한 파일** 생성. 데이터가 바뀌면 `node app/build.js`로 재생성. 생성물은 커밋한다(배포 파일).
- `<title>하데스2 빌드 길잡이</title>`를 파일 맨 위에. 파비콘은 배포 시 `🌙`.
- Artifact 제약: `<!doctype>/<html>/<head>/<body>` 태그 쓰지 않음, 외부 리소스 0, 다운로드 링크 0(내보내기는 텍스트 복사), 16MB 이하(예상 ~400KB).
- 데이터 인라인은 `<script type="application/json" id="h2-data">` 한 덩어리로 넣고 시작 시 `JSON.parse`. 엔진은 `<script>`로 인라인, `window.createHadesEngine` 사용.
