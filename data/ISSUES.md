## [P1] 슬롯 배타성 명시 + 헤르메스 칸 미점유로 확정 (종결)

사용자가 규칙을 확정해 주었다: **5칸(일반 공격 / 기술 / 마법 / 질주 / 마력)에는 신 1명의
은혜만 장착되며, 다른 신의 같은 칸 은혜를 받으면 기존 것이 사라지고 교체된다.**

이 규칙을 데이터에 대조해 보니 **헤르메스가 질주 슬롯에 은혜 2개**(거침없는 속도, 잰 발걸음)를
가지고 있어 모델과 모순됐다. 플레이 중 둘 다 보유 가능하므로 결론은 하나뿐이다 —
**헤르메스 은혜는 칸을 차지하지 않는다.** 위키의 Type 열은 "점유 칸"이 아니라
"강화하는 동작"을 뜻하는 것으로 판단했다. 아르테미스도 동일(전부 passive).

조치:
- 헤르메스 신속 대응/거침없는 속도/잰 발걸음 → `slot: passive` + `affects: ["cast"|"sprint"]`로 정정
- 칸 점유 은혜 45개(핵심 신 9 × 5칸)에 `occupies_slot: true` + `conflicts`(같은 칸의 다른 8개) 생성
- 생성은 `data/derive_slots.py`, 강제는 `validate.js` 검증 10번

### 판정 근거 (인게임 확인 불가 → 확률 높은 쪽으로 확정)

사용자가 인게임 확인이 어려워, 아래 근거로 **"칸 미점유"를 확정하고 진행**한다.

1. **헤르메스가 질주 강화 은혜를 2개 보유** (거침없는 속도, 잰 발걸음). 위키에 서로
   교체된다는 언급이 없고, 커뮤니티 빌드에서도 둘을 함께 든 사례가 보인다.
   칸을 점유한다면 성립할 수 없는 구성이다. — 가장 강한 근거
2. **게임 원문 전제조건이 "Any Ring Boon"이지 "Any Cast Boon"이 아니다.**
   번개 투창·달아오른 숯·성대한 환영·고기 분쇄 등은 전부 "고리(Ring)" 은혜를 요구한다.
   헤르메스 신속 대응이 마법 칸을 점유하는 정식 마법 은혜라면 게임이 조건을 굳이
   "고리"로 좁힐 이유가 없다. → 신속 대응은 마법 칸 밖에서 마법을 강화하는 것
3. **헤르메스는 융합 은혜가 없다** (위키 명시). 융합은 각 신의 칸 점유 은혜를 전제로
   설계된 시스템인데 헤르메스만 통째로 빠져 있는 것은 별도 카테고리라는 방증
4. 아르테미스는 위키에 Type 열 자체가 없다 (전부 미점유)

### 틀렸을 때의 비용과 되돌리는 법

- **틀렸을 경우 손해**: 엔진이 헤르메스 은혜를 추천할 때 "기존 질주 은혜를 버림" 경고를
  누락한다. 헤르메스 은혜는 대체로 무조건 이득이라 초보 기준 실피해는 작다.
- **반대로 잘못 점유로 잡았을 경우 손해가 더 크다**: 매번 "한풍 쇄도를 버리게 됩니다"라는
  틀린 경고가 떠서 사용자가 좋은 헤르메스 은혜를 피하게 된다. 비대칭도 현재 선택을 지지.
- **되돌리기**: `data/derive_slots.py`의 `NON_SLOT_GODS`에서 `"hermes"`를 빼고 다시 실행하면
  끝. 한 줄 수정 + 재실행이므로 나중에 플레이 중 반증이 나와도 즉시 반영 가능.

### 엔진(2-A)에 직접 영향

1. **교체 추천은 반드시 손실을 표시해야 한다.** "포세이돈 파도 일격 추천"이 사실은
   "제우스 천상 일격을 버림"을 뜻하는데 이걸 안 보여주면 초보가 손해를 본다.
2. **융합 조건은 현재 장착 중인 은혜 기준이다.** 칸을 교체하면 쌓고 있던 융합 조건이
   깨질 수 있다 → 교체 추천 시 "진행 중인 융합 N개가 무효화됨"을 감점으로 반영할 것.
3. 빈 칸 > 채워진 칸 순으로 가산점.

## [P1] 다이달로스 망치(무기 강화) 추가 수집 — `conflicts` 필드 신설

처음에는 "범위 밖"으로 판단해 뺐으나 **오판이었다.** 망치는 은혜와 똑같이 3개 중 1개를 고르는
선택 구조이고 무브셋 자체를 바꿀 만큼 파급이 커서 추천 대상에 반드시 들어가야 한다.
초반 4무기 전체를 다시 수집해 `data/hammers.json` (58개) 추가.

이 과정에서 **상충 관계를 표현할 필드가 필요해져 `conflicts` / `boon_conflicts`를 신설**했다.
아래 P1 항목(은혜 간 상충)도 같은 구조로 처리하면 되므로 2-A에서 통일할 것.

확인된 상충 (위키 명시):
- 지팡이 **고속 강타** ↔ 무리한 강타 / 십자 대격변 / 흡혈 대격변 (동시 채용 불가)
- **데메테르 잡초 박멸(Weak Killer)** ↔ 고속 강타(지팡이) / 고속 맹습(쌍검) / 고속 참격(도끼)
  → 은혜와 망치가 서로를 막는 유일한 사례. 엔진이 이걸 모르면 "잡초 박멸 먹어라"라고 한 뒤
  다음 방에서 "고속 참격 먹어라"라고 모순된 추천을 하게 됨

무브셋을 바꿔버리는 망치는 별도 취급 필요:
- **지옥 가르기**(도끼): 3연타 → 내려찍기 1회. 단발 피해 증폭(헤파이스토스)과는 궁합, '타격마다 발동'(제우스 정전기 충격 등)과는 상극
- **무리한 강타**(지팡이): 타격 2배 → '타격마다 발동' 은혜와 시너지
- 즉 **망치 선택이 이후 신 추천을 바꿔야 한다** — 엔진에서 망치를 빌드 상태의 일부로 취급할 것

## [P2] 아르카나 각성 "둘러싼 카드"의 인접 범위 (4-A)

달·운명의 각성 조건 "둘러싼 카드"를 **8방향 인접**으로 구현했다. 4방향(상하좌우)일 가능성도 있음.
- 8방향이면 달[1,5]의 이웃 = 영겁·밤그림자·밤 / 운명[5,1]의 이웃 = 요술사·뱃사공·투사들
- 4방향이면 달 = 영겁·밤 / 운명 = 요술사·투사들
게임에서 달 카드를 켜보면 바로 확인된다. 틀리면 `recommend.js`의 `arcAdjacent`만 고치면 됨.

## [P2] 아티팩트 셸에서 글씨가 작게 보임 (갤럭시 S26+ 크롬)

원인 미확정. claude.ai 아티팩트 페이지가 iframe 폭을 데스크톱 기준으로 잡아 축소 표시하는 것으로 추정.
4-B U1에서 vw 비례 글자 + 사용자 글자 크기 설정으로 대응. **정적 호스팅(GitHub Pages 등)으로 열면 문제가 없는지** 비교하면 원인이 확정됨.

## [P3] 정보성 메모

- **`power_tier`는 오퍼스의 임시 판단값**. 위키에 티어 표기가 없어 효과 텍스트 기준으로 S/A/B를 매겼다. 1-C에서 커뮤니티 근거로 재조정 필요
- `beginner_safe` / `duo_gateway` 태그도 마찬가지로 임시. 특히 `duo_gateway`는 "여러 융합의 전제가 되는 은혜"로 붙였는데, 실제 등장 빈도 기준으로 재검토 권장
- 헤르메스는 **융합 은혜가 없다** (위키 명시). 엔진이 헤르메스에 융합 접근도 점수를 주지 않도록 주의
- 아르테미스도 융합·정기 은혜 없음
- 왕의 강권 / 여왕의 강권은 서로를 파괴하는 관계 — 둘 다 추천하면 안 됨
- 용력(Strength) 아르카나는 죽음 저항이 있으면 효과가 꺼짐 → **죽음 카드와 동시 추천 금지**. 각인된 압정 기념품도 죽음 저항 취급이라 용력을 끔
- 순백 사슴뿔(최대 체력 30 고정)·불협화음 종(받는 피해도 증가)은 초보에게 위험 → `beginner_priority: 0`
- 물결 고리(Tidal Ring)의 물보라는 현재 마법 피해 증가 효과를 못 받는 버그 상태 (위키 기재)
