# 조사 지시서 (1-A, 페이블 → 1-B 오퍼스용)

## 목표
`SCHEMA.md` 구조대로 `data/*.json`을 채운다. **정확도 > 분량.** 확실하지 않은 건 `verified: false` + `ISSUES.md` 기록.
기준 버전: **하데스 2 정식판(v1.0, 2025-09) 이후 최신 패치.** 얼리액세스 시절 자료는 은혜 이름/수치가 달라진 경우가 많으니 날짜 확인.

## 출처 우선순위와 키

| 키 | 출처 | 용도 | 신뢰도 |
|---|---|---|---|
| `wiki` | hades.fandom.com (Hades II 섹션) | 은혜 목록·효과·듀오/전설 전제조건의 **1차 기준** | 높음 (영문) |
| `namu` | 나무위키 "하데스 2" 하위 문서 (은혜/무기/아르카나/유물) | **한글 명칭** 1차 기준 + 한국 커뮤니티 평가 | 한글명 높음, 평가는 참고 |
| `game8` | game8.co Hades 2 | 빌드 가이드·티어, 위키 교차검증 | 중간 |
| `reddit` | r/HadesTheGame (build, beginner, tier 검색) | 커뮤니티 정석 빌드, 초보 조언 | 중간 (다수 의견만 채택) |
| `kr_comm` | 인벤/루리웹/디시 하데스 갤러리 | 한국 커뮤니티 정석 빌드, 한글명 실사용 표기 | 중간 |
| `steam_kr` | Steam 한국어 가이드 | 한글명 보조 | 중간 |
| `video` | 유튜브 가이드 (Haelian 등 영문 스트리머, 한국 스트리머) | 티어 판단 보조. 텍스트 자료로 확인 가능한 것만 채택 | 낮음 |

**한글명 확정 규칙:** `namu` + (`kr_comm` 또는 `steam_kr`) 두 곳에서 같은 표기면 `verified: true`. 한 곳만 있으면 그 표기를 쓰고 `verified: false`. 표기가 갈리면 ISSUES에 양쪽 기록 후 나무위키 표기를 임시 채택.

## 작업 순서 (의존 순서대로)

1. **gods.json** — 신 목록·타입·저주. 가장 먼저. 저주 한글명 확정 후 `SCHEMA.md` 저주 표를 갱신.
2. **boons.json** — 핵심 신 9명 전부 → 헤르메스 → 아르테미스/셀레네/카오스 → NPC.
   - 신 1명 끝날 때마다 슬롯 5종이 모두 있는지 확인.
   - `tags`는 효과 텍스트에서 기계적으로 붙일 수 있는 것(저주 부여, 슬롯, Ω)을 우선. `beginner_safe`, `duo_gateway`는 4단계 이후 커뮤니티 자료 근거로만.
3. **duo_legendary.json** — 위키 전제조건을 그대로 옮기되, **boons.json의 id로 매핑**. 매핑 안 되는 이름이 나오면 boons.json 누락이니 거기부터 보강.
4. **weapons.json** — 초반 4무기 + 양상. `favored_gods`/`favors`는 `BUILD_DIRECTIONS.md`와 커뮤니티 빌드 가이드 기준.
5. **arcana.json**, **keepsakes.json**, **hexes.json**
6. **validate.js** 작성·실행 → 오류 0 → ISSUES.md 정리 → HANDOFF 체크·로그.

## 항목별 체크리스트

### gods.json
- [ ] 핵심 신 9명: 아프로디테·아폴론·아레스·데메테르·헤파이스토스·헤라·헤스티아·포세이돈·제우스
- [ ] 비핵심: 헤르메스, 아르테미스, 셀레네, 카오스, 아라크네, 이카로스, 나르키소스, 에코, 메데이아, 키르케 (+ 정식판에 추가된 소스 있으면)
- [ ] 각 신의 저주 영문/한글명, 저주 기본 메커니즘 한 줄
- [ ] `theme`, `beginner_note` — 초보가 이 신을 언제 집어야 하는지 한 줄

### boons.json
- [ ] 핵심 신 9명 × 전체 은혜 (슬롯형 + 패시브형 + 상위 은혜)
- [ ] 각 은혜 `prereq` (상위 은혜가 요구하는 하위 은혜)
- [ ] `effect` 30자 내외 한글 요약, 수치는 Common 기준
- [ ] 헤르메스 전체
- [ ] 아르테미스 전체 (조우형)
- [ ] 카오스 은혜: 저주/축복 구조만 요약 (개별 항목 전부 넣지 않아도 됨, ISSUES에 범위 기록)
- [ ] NPC 은혜: 이름·효과만

### duo_legendary.json
- [ ] 듀오 은혜 전부 (핵심 신 9명 조합)
- [ ] 전설 은혜 신별 1개
- [ ] `requires`를 위키 원문 그대로 → id 매핑. **AND/OR 구조를 임의로 단순화하지 말 것**
- [ ] `power_tier` — game8/reddit 다수 의견. 근거 없으면 `"?"`

### weapons.json
- [ ] 초반 4무기 한글 정식 표기 (나무위키/인게임): 지팡이·자매의 검·그림자 화염(가칭)·월장석 도끼(가칭)
- [ ] 각 무기 기본 양상(멜리노에) + 해금 양상 2개 + 숨겨진 양상(있으면 `hidden: true`)
- [ ] 양상 효과·해금 조건
- [ ] `core_slots`, `favored_gods`는 BUILD_DIRECTIONS.md 참고 + 커뮤니티 근거

### arcana.json
- [ ] 카드 전체 (25장 이상), grasp 비용, 효과, 각성 조건
- [ ] `beginner_priority` — 커뮤니티 "초보 아르카나 세팅" 자료 근거. 자주 언급되는 카드(예: 죽음 회피, 마력 관련, Ω 관련, 신 선택지 재선택) 우선

### keepsakes.json
- [ ] 유물 전체, 지급 NPC, 효과
- [ ] 신 유물(특정 신 등장 유도) `kind: god_favor` + `god` 연결 — **엔진에서 "이 신 노리려면 이 유물" 추천에 직접 쓰임**
- [ ] 초보 추천 순위

### hexes.json
- [ ] 셀레네 헥스 전체, 충전 마력, 효과

## 하지 말 것
- 얼리액세스(2024~2025.8) 자료를 최신으로 오해해서 넣기 → 날짜 확인 필수
- 전제조건 AND/OR 임의 단순화
- 한글명 직접 번역해서 만들기 → 확인 안 되면 영어 그대로 두고 `verified: false`
- 수치 정밀도에 시간 쓰기 → 효과 요약과 관계·조건이 핵심. 수치는 Common 기준 대략치로 충분

## 완료 기준
- `node data/validate.js` 오류 0
- `verified: false` 항목이 전체의 20% 이하 (넘으면 ISSUES에 사유)
- `ISSUES.md`에 페이블 리뷰(1-C) 때 봐야 할 항목이 우선순위 순으로 정리됨
- HANDOFF.md 1-B 체크 + 진행 로그 1줄
